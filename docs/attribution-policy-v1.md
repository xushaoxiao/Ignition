# 归因规则 v1

> **这份文档是产品的一部分，对客户与 KOL 公开。**
>
> 每条归因记录都会存下当时的 `policy_version`，任何一笔历史账单都能按对应版本
> 精确复算。规则变更必须发布新版本号并提前 30 天通知；老客户可在一个账期内
> 沿用旧版本。我们不会静默修改规则。

## 为什么公开

我们同时收取平台费和效果分成。如果只收效果分成，我们的收入会随着我们报出的
数字线性增长 —— 那样客户理性上就应该怀疑每一个数字。平台费的存在，让我们不
依赖数字大小赚钱；规则公开，让任何人都能自己验算。

## 规则表

| 项目 | v1 取值 | 说明 |
|---|---|---|
| 归因模型 | Last-touch | 最后一次点击的 KOL 获得归因 |
| 点击归因窗口 | 7 天 | 超过则该点击失效 |
| 领奖码有效期 | 24 小时 | 超时需重新完成游戏 |
| 单归因 | 是 | 一个用户只归属一个 KOL，不做分成拆分 |
| 归因锁定期 | 90 天 | 期内该用户的转化都算原 KOL |
| 可计费归因方式 | `deterministic_code` / `install_referrer` / `universal_link` | 见下表 |
| activation 冷静期 | 7 天 | 期内可冲正 |
| iap_purchase 冷静期 | 35 天 | 覆盖 App Store 退款窗口 |

## 归因方式与计费

| 方式 | 说明 | 置信度 | 是否计费 |
|---|---|---|---|
| `deterministic_code` | 用户输入领奖码核销 | 100 | ✅ |
| `install_referrer` | Android Play Install Referrer 自动带参 | 100 | ✅ |
| `universal_link` | 已安装用户直接唤起，参数在 URL 里 | 100 | ✅ |
| `clipboard_match` | 剪贴板匹配 | 60 | ❌ |
| `probabilistic` | 指纹 / 时间窗匹配 | 30 | ❌ |

**只有确定性归因才计费。** 概率归因的转化会出现在看板上，但不会出现在账单上。

这不是保守，是现实：iOS 17+ 之后，user-level 的 deferred deep link 已经不存在
可靠实现 —— IDFA 拿不到，指纹匹配精度崩塌，AdAttributionKit 只给聚合的、延迟
的回传。任何声称能在 iOS 上做到 100% 自动归因并按此计费的方案，都在向你收一笔
它自己也无法验证的钱。

## 看板上的两个数字

看板会同时显示：

- **归因转化（全部）** —— 含概率归因，用于评估渠道质量
- **可结算转化** —— 仅确定性归因且通过风控，这是账单口径

两者的差额会被拆解展示，例如：

```
归因转化 500
 ├─ 确定性归因 420   ← 计费
 ├─ 概率归因    60   ← 不计费
 └─ 风控暂缓    20   ← 待人工复核
```

我们主动把差异摆出来。你自己发现差异再来问，比我们先说，对双方都更糟。

## 封顶

超出月度封顶的转化**照常归因、照常给 KOL 记功，只是不向你收费**，在账单和看板
上标记为「已超出封顶（免费）」。我们不会因为你用超了就停止服务。

## 冲正

以下情况会产生冲正（写反向分录，不修改原记录）：

- 主 App 报告该笔交易退款
- 风控事后判定为异常流量
- 申诉复核后判定归因无效

已开票的转化被冲正时，走下个账期的信用额度（credit），不追溯修改已出账单。

## 申诉

对任一条归因记录有异议，可发起申诉：

1. 该条记录立即冻结，暂停结算
2. 我们提供该条记录的完整证据快照（`evidence` 字段）：领奖码、核销时间、
   设备与 IP、风控判定结果
3. 复核结论写入记录，可冲正
4. 申诉记录本身可查询

证据快照在写入后不可修改。
